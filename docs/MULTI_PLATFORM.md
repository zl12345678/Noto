# Noto · 知微 — 多端路线图

> 本文定义 **先做什么端、怎么做、功能边界**，与 [技术架构设计.txt](../技术架构设计.txt)、[前端工程初始化说明.md](../前端工程初始化说明.md) 中的「Web 优先、API 复用」原则一致。  
> 部署见 [DEV_DEPLOY.md](./DEV_DEPLOY.md)，发版回归见 [E2E_CHECKLIST.md](./E2E_CHECKLIST.md)。

---

## 1. 核心结论

| 问题 | 答案 |
|------|------|
| **现在主攻** | Web 桌面浏览器（Vue 3，MVP ~95%） |
| **第一个新端** | **移动 Web / PWA**（同一仓库渐进增强） |
| **暂不做** | 原生 App、小程序、桌面壳（除非有明确数据或渠道需求） |
| **架构原则** | API 优先 · 业务在后端 · 表现层按端独立 |

**一句话**：不是「五个客户端同时开干」，而是 **一个 API 内核 + 按使用场景分端的体验层**。

---

## 2. 平台优先级

```text
阶段 0（现在）      Web 桌面浏览器           ← 主战场，继续打磨闭环
        ↓
阶段 1（下一版）    移动 Web / PWA           ← 第一个新平台，成本最低
        ↓
阶段 2（按需）      桌面壳 Tauri / Electron  ← 系统通知、离线、全局快捷键
        ↓
阶段 3（数据驱动）  原生 App Flutter / RN    ← 推送、离线编辑、剪藏
        ↓
阶段 4（渠道驱动）  小程序（功能子集）        ← 仅在有微信等分发需求时
```

### 2.1 各端定位

| 平台 | 优先级 | 用户场景 | 与现状 |
|------|--------|----------|--------|
| **Web 桌面** | P0 | 深度写作、AI、看板、演示部署 | 已实现 |
| **移动 Web / PWA** | **P1** | 与桌面同功能集，移动布局适配 | `ResponsiveLayout` + 验收 [MOBILE_WEB_CHECKLIST.md](./MOBILE_WEB_CHECKLIST.md) |
| **桌面壳** | P2 | 常驻、系统通知、Cmd+K 全局 | 未开始 |
| **原生 App** | P3 | 推送、离线、相机剪藏 | 未开始 |
| **小程序** | P4 | 微信生态引流、只读/轻操作 | 未开始 |

### 2.2 为什么下一版是移动 Web，而不是原生 App

1. **后端已 API 化**：REST + JWT + SSE，`frontend/src/api/` 统一封装，新端换壳即可。
2. **验证成本低**：同一 Vue 仓库渐进增强，无需维护第二套 UI 框架。
3. **产品价值匹配**：手机端「看今日待办 → 点提醒 → 读笔记 → 改状态」不依赖原生能力。
4. **小程序 / 原生不适合第一跳**：长文 MD 编辑、SSE 流式 AI、MinIO 附件在小程序受限；原生重写编辑器与智能体成本高，而 Web MVP 仍在迭代。

## 3. 架构分层

```text
┌─────────────────────────────────────────┐
│  表现层（按端独立，不强行共享 UI）         │
│  Web 桌面 │ 移动 Web/PWA │ App │ 桌面壳   │
├─────────────────────────────────────────┤
│  契约层（越早标准化越好）                  │
│  OpenAPI · 统一 DTO · 错误码 · 鉴权约定    │
├─────────────────────────────────────────┤
│  能力层（Spring Boot 单体，已基本完成）    │
│  笔记 · 搜索 · AI/RAG · 待办 · 提醒 · 审计 │
└─────────────────────────────────────────┘
```

### 3.1 共享 vs 不共享

| 多端共享 | 各端独立 |
|----------|----------|
| REST / SSE 契约 | 页面布局与导航结构 |
| 鉴权流程（JWT Bearer） | Markdown 编辑器实现 |
| 领域概念（笔记、待办、horizon、状态） | 拖拽、Cmd+K 等桌面交互 |
| 错误码、分页、路由 query（如搜索 `start/end/q`） | 组件库（Ant Design Vue vs 移动端组件） |
| 可抽离 `packages/api-client`（TypeScript） | 推送通道实现 |

### 3.2 后端为多端预留的三件事

| 方向 | 说明 | 状态 |
|------|------|------|
| **契约稳定** | SpringDoc 导出 OpenAPI，多端生成 SDK | 待做 |
| **鉴权扩展** | JWT + `deviceId`、refresh token、按端 scope | 待做 |
| **推送抽象** | `NotificationChannel`：browser / webpush / fcm / apns | 待做（当前仅浏览器 Notification + 轮询） |

业务规则（提取待办、RAG、智能体编排）**只放在后端**，各端禁止复制。

## 4. 功能矩阵（避免「全平台全功能」）

| 能力 | Web 桌面 | 移动 Web/PWA | 原生 App | 小程序 |
|------|----------|--------------|----------|--------|
| 长文 Markdown 编辑 | ✅ 完整 | ⚠️ 分阶段（先读后写） | ⚠️ 分阶段 | ❌ 不建议 |
| 行动看板拖拽 | ✅ | ⚠️ 改为按钮/滑动 | ✅ 原生手势 | ⚠️ 列表为主 |
| Cmd+K / 全局指令 | ✅ | ⚠️ 底部搜索栏 | 可选 | ❌ |
| AI 流式问答 | ✅ | ✅ | ✅ | ⚠️ 限长/非流式 |
| RAG / 智能体多步 | ✅ | ⚠️ 简化 | 分阶段 | ❌ |
| 规则/AI 提取待办 | ✅ | ⚠️ Phase B | 分阶段 | ❌ |
| 到期 / 逾期提醒 | 浏览器通知 | PWA + 轮询 | **系统推送** | 模板消息 |
| 附件 / 图片 | MinIO | ✅ | ✅ | 强受限 |
| 离线 | ❌ | ⚠️ PWA 缓存已读内容 | ✅ | ❌ |

**产品表述**：

- **桌面** = 深度写作与 AI 编排  
- **移动** = 行动、提醒、轻量阅读与录入  
- **小程序** = 引流 / 只读子集（若做）

## 6. 移动 Web MVP

### 6.1 目标

在 **不新建仓库、不重写后端** 的前提下，让手机浏览器（或可安装 PWA）完成：

> **登录 → 看今日行动 → 改待办状态 → 读笔记 → 收提醒 → 简单搜索**

复杂写作、多步智能体、拖拽看板完整体验仍引导用户使用 **Web 桌面**。

### 6.2 信息架构（Mobile）

```text
底部 Tab（建议 4 个）
├── 首页      今日行动（简化看板：队列 / 进行中 / 完成计数）
├── 笔记      知识库列表 → 笔记阅读（Phase A）→ 轻量编辑（Phase B）
├── 待办      行动看板列表视图（无拖拽，按钮改状态）
└── 我的      提醒列表、设置、通知权限、退出

全局
└── 顶栏搜索  替代 Cmd+K（关键字 + 跳转笔记）
```

### 6.3 页面清单与 Phase

#### Phase A — 可读可行动（优先交付）

| 页面 / 模块 | 路由参考 | 桌面复用 | 移动改造要点 |
|-------------|----------|----------|--------------|
| 登录 / 注册 | `/login` `/register` | 高 | 单栏、大按钮、`100dvh` 防 Safari 跳动 |
| 首页看板 | `/` | 中 | 三列 Kanban → 纵向卡片 + 状态按钮 |
| 待办列表 | `/todos?view=board` | 中 | 列表 + 滑动/按钮改状态 |
| 提醒 | `/reminders` | 高 | 列表 + 跳转关联待办/笔记 |
| 笔记列表 | `/notes` | 中 | 单栏树/列表，隐藏复杂侧栏 |
| 笔记阅读 | `/notes/:id` | 中 | 渲染 MD 预览为主，隐藏宽屏编辑器 |
| 搜索 | `/search` 或顶栏 | 高 | 结果列表，跳转阅读页 |
| 设置 / 个人 | `/profile` | 高 | 通知权限、AI 开关说明 |

#### Phase B — 可轻量写入（第二阶段）

| 页面 / 模块 | 说明 |
|-------------|------|
| 笔记轻量编辑 | textarea + 预览，或移动端 MD 组件；非 CodeMirror 全功能 |
| 快捷录入 | 新建笔记模板、`- [ ]` 待办行 |
| 规则提取待办 | 阅读页入口 → 预览 → 确认 |
| 图片上传 | 依赖 MinIO，需 `noteId` 已保存 |
| AI 单条摘要 | 抽屉内非流式或短流式 |

#### Phase C — PWA 增强

| 项 | 说明 |
|----|------|
| `manifest.json` | 名称、图标、`display: standalone` |
| Service Worker | 静态资源缓存；可选缓存最近阅读的笔记 JSON |
| 安装提示 | 满足条件时引导「添加到主屏幕」 |
| 离线 | 仅「已加载过的笔记只读」，写操作需联网 |

### 6.4 技术实现要点（前端）

```text
frontend/src/
├── layouts/
│   ├── AppLayout.vue          # 现有桌面布局
│   └── MobileLayout.vue       # 新增：底 Tab + 顶栏
├── composables/
│   └── useBreakpoint.ts         # 统一 breakpoint（建议 md: 768px）
├── views/ ...                   # 按 breakpoint 切换布局或拆 mobile 子组件
└── styles/
    └── mobile.css               #  touch-action、safe-area、100dvh
```

**Breakpoint 建议**：

| 宽度 | 布局 |
|------|------|
| `< 768px` | `MobileLayout` |
| `≥ 768px` | 现有 `AppLayout`（桌面三栏） |

**交互降级规则**：

| 桌面 | 移动 |
|------|------|
| 拖拽改待办状态 | 「开始 / 完成 / 退回队列」按钮 |
| Cmd+K | 顶栏搜索图标 |
| 侧栏 AI 抽屉 | 全屏 Bottom Sheet |
| 编辑器分屏预览 | 阅读页 + 独立编辑页 |

### 6.5 验收标准（Phase A）

在 **Chrome 移动模拟器 + 真机 iOS Safari / Android Chrome** 上完成：

#### 路径 1：登录与首页

- [ ] 登录 `admin` / 演示账号，无横向滚动条、无布局溢出
- [ ] 首页展示今日待办队列与进行中（卡片列表）
- [ ] 点击待办「开始」→ 状态变为进行中；「完成」→ 进入今日完成

#### 路径 2：笔记阅读

- [ ] 笔记列表可进入「周会纪要 · MVP 演示」
- [ ] Markdown 正文可读（标题、列表、checkbox 渲染正常）
- [ ] 从笔记可跳转关联待办 / 看板

#### 路径 3：提醒

- [ ] 提醒列表可打开，到期项可点击跳转
- [ ] 首次进入引导开启浏览器通知（与桌面逻辑一致）
- [ ] 通知权限拒绝时，页内仍有提醒展示（不静默失败）

#### 路径 4：搜索

- [ ] 顶栏搜索「Q2」→ 命中笔记 → 跳转阅读页
- [ ] 搜索结果无需 CodeMirror 正文定位（Phase A 可只做标题/摘要高亮）

#### 路径 5：回归桌面

- [ ] 同一账号在桌面宽度（≥768px）下仍为完整三栏体验
- [ ] 移动端改过的待办状态与桌面看板数据一致

**非目标（Phase A 不要求）**：

- 移动端完整 Markdown 编辑 parity
- 看板拖拽、Cmd+K、智能体多步确认
- 离线编辑、Web Push（属 Phase C）

### 6.6 验收标准（Phase B，补充）

- [ ] 新建笔记并保存（轻量编辑器）
- [ ] 规则提取待办：预览 → 确认 → 看板可见
- [ ] 上传图片并插入 Markdown（需 MinIO 开启）
- [ ] AI 摘要单篇笔记（流式或短响应均可）

## 7. 后续端（简要方向）

### 7.1 桌面壳（Tauri 优先于 Electron）

- 打包现有 `frontend` 生产构建
- 系统托盘、原生通知、全局快捷键（Cmd+K）
- 本地草稿缓存（可选）

### 7.2 原生 App

- **触发条件**：移动 Web DAU / 7 日留存达标，或推送成为刚需
- **技术**：Flutter 或 RN + OpenAPI 生成客户端
- **第一版范围**：读笔记 + 待办 + 推送 + 剪藏导入（`NoteClipImport` 已有 API 可复用）

### 7.3 小程序

- **触发条件**：明确微信/企微分发渠道
- **范围**：只读笔记、待办列表、提醒；不做完整编辑器与智能体
- **后端**：独立 `clientId`、更短 token 有效期、接口子集
