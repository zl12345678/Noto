# Noto AI Resume Demo

> 目标：用 3 分钟把 Noto 讲成“AI 工程项目”，而不是“普通笔记 + 大模型 API”。

---

## 1. 一句话定位

Noto 不是通用聊天机器人，而是一个 AI 知识工作台：把私人笔记检索、理解并转化成待办、提醒和复盘。

---

## 2. 3 分钟演示路径

### 0:00 - 0:30 打开 AI 展示页

打开：

```text
/ai-showcase
```

讲解重点：

- AI provider 和 model 来自真实配置。
- RAG chunks / indexed notes 来自知识库索引状态。
- Agent runs 展示最近自然语言办事记录。

建议话术：

> 这个页面不是业务主入口，是我为面试和自测准备的 AI 工程展示页。它把 RAG、Agent、自动化任务和简历亮点集中到一个地方。

### 0:30 - 1:10 展示 RAG 问答

打开 AI 助手，提问：

```text
这个知识库里关于项目部署有哪些注意事项？
```

讲解重点：

- 回答不是裸模型生成，而是基于知识库召回。
- 引用文档可点击跳转。
- 如果资料不足，会提示知识缺口。

建议话术：

> 这里的关键不是“能回答”，而是回答有来源。RAG 召回把私有笔记变成模型上下文，引用跳转让回答可检查。

### 1:10 - 2:00 展示可确认 Agent

输入：

```text
把最近的会议纪要整理成待办，并给明天下午的任务设提醒
```

讲解重点：

- 意图路由会判断进入 agent，而不是普通 chat。
- Agent 拆成搜索文档、摘要、提取待办、创建提醒等步骤。
- 写操作需要用户确认。

建议话术：

> 我没有让 AI 静默写库。所有涉及创建、修改、删除的步骤都会进入确认链路，并写入任务记录和审计日志。

### 2:00 - 2:40 展示知识到行动闭环

打开待办或首页：

- 查看 AI 提取出的待办。
- 开始执行。
- 完成后生成一句复盘并回写原笔记。
- 展示每日 digest 或周报草稿。

建议话术：

> 这个项目的差异点是“知识到行动”。不是把 AI 放在侧边栏，而是把它嵌进记录、提取、执行、提醒、复盘的主流程。

### 2:40 - 3:00 总结工程能力

总结：

- LangChain4j + DashScope 接入。
- pgvector RAG。
- SSE 流式回答。
- 可确认 Agent。
- 审计日志。
- Docker 部署与集成测试。

## 3. 简历 Bullet

可直接写入简历：

- 基于 `LangChain4j + DashScope + pgvector` 构建私有知识库 RAG 系统，支持文档分块、embedding 索引、HNSW 向量检索、关键词混合召回、SSE 流式回答与引用跳转。
- 设计可确认 AI Agent 工作流，将自然语言指令拆解为搜索文档、摘要、提取待办、创建提醒等工具调用，所有写操作支持预览确认与审计追踪。
- 围绕“知识 → 行动”闭环实现摘要、待办提取、任务拆解、逾期建议、每日 digest、周报复盘等 AI 能力，并接入笔记、待办、提醒核心业务流。
- 建设 Docker 化生产部署、pgvector 检索、MinIO 附件存储、集成测试与演示数据种子，支持完整项目演示和私有化部署。

## 4. 面试追问准备

### Q：这和普通调用大模型 API 有什么区别？

答：

> 普通调用 API 只解决生成。这个项目有检索、引用、可确认工具调用、业务写入、审计和复盘闭环。模型只是能力之一，重点是 AI 如何安全进入业务流程。

### Q：如何降低幻觉？

答：

> 用 RAG 把私有知识召回进上下文，并返回引用。回答不足时给知识缺口提示；评测上用固定问题检查引用命中率和要点覆盖率。

### Q：为什么不让 Agent 自动执行？

答：

> 因为笔记、待办、提醒都是用户数据。简单读操作可以自动完成，写操作进入确认链，保证可控和可回滚。

### Q：如果 AI 服务不可用怎么办？

答：

> 后端支持 AI disabled fallback，非 AI 主流程仍可用；部分待办提取有 Markdown 规则兜底。
