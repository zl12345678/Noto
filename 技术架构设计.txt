技术架构设计

一、架构目标
1. 当前先做 Web 端，保证产品快速上线
2. 架构预留多端通用能力，后续可扩展到 iOS、Android、小程序、桌面端
3. 支持个人知识管理、AI 问答、待办提醒、任务型智能体
4. 优先保证可用性、可扩展性和可维护性

二、总体架构原则
1. 前后端分离
- Web 端仅作为一个客户端形态
- 后续多端共享同一套后端 API

2. API 优先
- 所有核心能力通过统一 API 提供
- 统一鉴权、统一错误码、统一数据结构
- 便于未来接入移动端和桌面端

3. 核心业务模块化
- 笔记模块
- 搜索模块
- AI 模块
- 待办模块
- 提醒模块
- 用户与权限模块
- 审计与日志模块

4. AI 与业务解耦
- AI 只作为能力层，不直接侵入业务数据结构
- 笔记、待办、提醒都通过服务层进行编排
- 便于后续替换模型或接入多个模型

三、整体系统分层
1. 表现层
- Web 前端
- 后续扩展 App、桌面端、小程序

2. 接口层
- REST API
- WebSocket 或 SSE 用于 AI 流式输出、提醒推送、实时通知

3. 业务服务层
- 用户服务
- 笔记服务
- 搜索服务
- AI 服务
- 待办服务
- 提醒服务
- 智能体编排服务

4. 数据层
- PostgreSQL：核心业务数据
- Redis：缓存、会话、任务状态、限流
- Elasticsearch 或 OpenSearch：全文检索
- 向量存储：可先与检索层同库或使用独立向量方案
- MinIO：图片、附件、导出文件

5. 基础设施层
- 消息队列：异步任务、索引构建、提醒触发
- 定时任务：提醒扫描、日报周报生成
- 日志与监控：调用链路、错误日志、性能监控

四、推荐技术栈
1. 后端
- Java 21
- Spring Boot 3
- Spring Security
- Spring Data JPA 或 MyBatis Plus
- Spring AI 或自定义 LLM 接入层
- WebSocket / SSE
- Quartz 或 Spring Scheduler

2. 前端 Web
- Vue 3 或 React
- TypeScript
- Vite
- UI 组件库：Ant Design Vue、Arco Design、Element Plus 任选其一
- Markdown 编辑器：TipTap、Milkdown 或 MarkDown 编辑器方案

3. 基础服务
- PostgreSQL
- Redis
- Elasticsearch / OpenSearch
- MinIO
- RabbitMQ 或 Kafka

五、服务模块设计
1. 用户与认证模块
职责：
- 注册登录
- Token 认证
- 用户资料
- 登录态管理
- 后续支持多端统一登录

2. 笔记模块
职责：
- 笔记创建、编辑、删除
- 文件夹、标签、收藏
- 草稿自动保存
- 笔记内容版本基础记录
- 生成索引任务

3. 搜索模块
职责：
- 标题搜索
- 内容搜索
- 标签过滤
- 文件夹过滤
- 高亮命中内容
- 返回原文定位

4. AI 模块
职责：
- 笔记总结
- 问答生成
- 待办提取
- 风险点识别
- 相关文档推荐
- 流式返回结果

5. 待办模块
职责：
- 待办创建、修改、完成、过期
- 待办来源回链
- 优先级管理
- 状态流转

6. 提醒模块
职责：
- 到期提醒
- 每日提醒
- 每周总结提醒
- 重要事项提醒
- 后续支持外部通知通道

7. 智能体编排模块
职责：
- 接收用户目标
- 拆解任务步骤
- 调度搜索、总结、待办、提醒等工具
- 处理用户确认
- 记录执行过程

8. 审计与日志模块
职责：
- 记录 AI 调用链路
- 记录工具调用
- 记录任务执行结果
- 记录失败原因与异常信息

六、前端 Web 架构设计
1. 页面结构
- 首页
- 笔记列表页
- 笔记编辑页
- 笔记详情页
- AI 问答页
- 待办列表页
- 提醒页
- 搜索结果页
- 设置页

2. 状态管理
- 用户信息
- 当前工作区
- 笔记列表状态
- 当前笔记内容
- AI 会话状态
- 待办与提醒状态

3. 交互设计原则
- 编辑即时保存
- AI 面板固定在右侧
- 搜索入口全局可见
- 待办与提醒在首页有明显入口
- 所有 AI 结果可回链到原文

七、API 设计原则
1. 统一 REST 风格
- GET 查询
- POST 新增
- PUT/PATCH 更新
- DELETE 删除

2. 统一响应结构
- code
- message
- data
- traceId

3. 统一错误处理
- 参数错误
- 鉴权失败
- 权限不足
- 资源不存在
- AI 服务失败
- 外部依赖异常

4. 统一鉴权方式
- Web 端与未来多端共用同一 Token 体系
- 预留刷新 Token 机制

八、AI 与智能体设计
1. AI 能力入口
- 文档总结
- 文档问答
- 待办抽取
- 风险识别
- 任务执行

2. RAG 流程
- 用户提问
- 召回相关笔记片段
- 组合上下文
- 调用大模型生成答案
- 返回引用来源

3. 任务型智能体流程
- 用户提出目标
- 智能体拆解子任务
- 调用搜索、总结、待办、提醒等工具
- 用户确认后写回系统

4. 流式输出
- AI 回答采用流式输出
- 提升可用性与交互感

九、数据存储设计原则
1. PostgreSQL 存储核心业务数据
- 用户
- 笔记
- 标签
- 待办
- 提醒
- 审计日志

2. Elasticsearch 存储检索索引
- 文档标题
- 文档内容分片
- 标签与关联字段

3. Redis 存储临时状态
- 登录会话
- AI 会话上下文
- 草稿缓存
- 任务状态
- 限流计数

4. MinIO 存储非结构化文件
- 图片
- 附件
- 导出文件

十、多端通用预留方案
1. API 层统一
- Web、移动端、桌面端共用一套接口

2. 业务领域统一
- 前端只负责表现
- 业务逻辑全部在后端服务层

3. 页面适配策略
- 当前 Web 优先
- 后续可采用响应式布局，兼容移动端浏览器

4. 认证统一
- 后续 App、小程序共用同一用户体系
- Token、刷新机制、设备识别统一设计

十一、部署架构建议
1. 开发环境
- 本地单体部署
- Docker Compose 启动数据库、Redis、ES、MinIO

2. 生产环境第一版
- 单体后端 + Web 前端分离部署
- 后端单实例起步
- 数据库与检索服务独立

3. 后续扩展
- AI 服务可单独拆分
- 检索服务可独立拆分
- 提醒和任务执行可异步化

十二、推荐的第一版架构边界
1. 先不拆微服务
- 先以模块化单体为主
- 保持代码边界清晰
- 为未来拆分预留接口

2. 先不做复杂多端适配
- 先把 Web 端体验做顺
- 通过统一 API 为未来多端铺路

3. 先不做复杂协作
- 先支持单人知识管理
- 后续再扩展团队空间和权限

十三、第一版关键技术决策
- Web 端优先，响应式预留移动端
- 后端采用模块化单体架构
- AI 能力通过独立服务层封装
- 检索与向量化能力独立于业务核心
- 任务与提醒通过异步机制处理
- 所有结果都要可追踪、可回链、可审计
