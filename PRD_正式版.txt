Noto · 知微
产品需求文档（PRD）正式版

文档版本：V1.0
日期：2026-05-30

一、产品概述
1.1 产品名称
Noto · 知微

1.2 产品定位
Noto · 知微是一款面向个人用户的 AI 知识管理与行动清单工具。产品支持笔记记录、知识检索、AI 问答、待办提取与提醒执行，目标是帮助用户将零散信息沉淀为结构化知识，并进一步转化为可执行的行动。

1.3 产品愿景
让用户不仅能够记录知识，还能够快速找到知识、准确理解知识，并将知识自动转化为行动。

1.4 产品目标
- 提供轻量、易用的个人知识管理能力
- 提供基于 AI 的知识理解与问答能力
- 提供自动提取待办与提醒的行动管理能力
- 为后续多端扩展预留统一架构

1.5 目标用户
- 程序员
- 产品经理
- 学习型用户
- 自由职业者
- 有个人知识整理与行动管理需求的人群

二、问题定义
2.1 用户痛点
- 笔记分散，难以快速检索
- 记录很多，但无法有效沉淀为知识
- 文档内容较长，重点不易提炼
- 记录与行动脱节，容易遗漏待办
- 需要周期性提醒，但手动维护成本高

2.2 解决方案
通过“记录 -> 理解 -> 提取 -> 提醒 -> 执行”的闭环，把知识管理和行动管理连接起来。

三、产品范围
3.1 本期范围（MVP）
- 用户注册、登录、基础鉴权
- 笔记创建、编辑、删除、收藏
- 文件夹与标签管理
- Markdown 编辑器
- 全文搜索
- AI 总结
- AI 问答
- 待办提取
- 提醒功能
- 基础审计日志

3.2 未来扩展范围
- 多人协作
- 共享空间
- 文档评论
- 权限体系
- 多端应用
- 任务型智能体编排
- 外部消息通知集成
- 知识图谱与双向链接

四、产品核心理念
4.1 核心理念
- 记录知识
- 理解知识
- 提炼行动
- 触发提醒
- 完成闭环

4.2 产品差异化
与传统笔记工具相比，Noto · 知微更强调 AI 对知识的理解能力，以及从知识到行动的自动化转化能力。

五、功能需求
5.1 用户与基础能力
5.1.1 用户注册
- 用户可使用邮箱或其他基础方式注册
- 注册后生成唯一用户身份

5.1.2 用户登录
- 用户可使用账号密码登录
- 支持基础会话保持

5.1.3 用户信息管理
- 支持修改昵称、头像等基础资料
- 支持基础账号设置

5.1.4 工作区管理
- 默认支持个人工作区
- 后续支持共享工作区扩展

5.2 笔记管理
5.2.1 新建笔记
- 用户可快速创建空白笔记
- 支持标题与正文编辑

5.2.2 编辑笔记
- 支持 Markdown 编辑
- 支持标题、列表、代码块等基础格式
- 支持草稿自动保存

5.2.3 删除笔记
- 用户可删除自己创建的笔记

5.2.4 收藏笔记
- 用户可将高频使用的笔记标记为收藏

5.2.5 文件夹与标签
- 支持文件夹分类
- 支持标签分类
- 支持按标签和文件夹筛选

5.2.6 最近编辑
- 自动记录最近编辑内容
- 方便快速返回工作内容

5.3 搜索与检索
5.3.1 全文搜索
- 支持标题搜索
- 支持正文搜索
- 支持标签搜索

5.3.2 搜索结果展示
- 支持结果高亮
- 支持原文定位
- 支持按相关性排序

5.4 AI 能力
5.4.1 笔记总结
- 自动生成笔记摘要
- 自动提炼关键结论
- 自动识别风险点

5.4.2 AI 问答
- 用户可就单篇笔记提问
- 用户可就整个知识库提问
- 回答需附带引用来源

5.4.3 相关文档推荐
- 根据当前笔记内容推荐相关笔记
- 根据主题推荐历史内容

5.5 待办管理
5.5.1 待办提取
- AI 可从笔记中识别待办事项
- 提取截止时间、优先级、来源文档

5.5.2 待办状态管理
- 未开始
- 进行中
- 已完成
- 已过期

5.5.3 待办回链
- 待办可跳转回对应原文笔记

5.6 提醒功能
5.6.1 到期提醒
- 支持对待办事项设置到期提醒

5.6.2 周期提醒
- 支持每日提醒
- 支持每周总结提醒

5.6.3 重要事项提醒
- 支持重要事项显著提醒

5.7 审计与日志
- 记录 AI 调用日志
- 记录工具调用日志
- 记录任务执行日志
- 记录错误日志

六、用户流程
6.1 笔记记录流程
1. 用户新建笔记
2. 输入内容
3. 系统自动保存草稿
4. 用户保存后进入索引流程
5. AI 可生成总结与待办

6.2 知识问答流程
1. 用户输入问题
2. 系统检索相关笔记片段
3. 组合上下文
4. 调用模型生成回答
5. 返回答案与引用来源

6.3 待办提醒流程
1. AI 从笔记中提取待办
2. 用户确认待办
3. 系统创建提醒
4. 到期触发提醒
5. 用户完成后更新状态

七、非功能需求
7.1 性能要求
- 页面加载响应快速
- 搜索结果应具备良好响应速度
- AI 回答支持流式输出

7.2 可用性要求
- 基础功能稳定可用
- 数据保存可靠
- 异常场景下有明确提示

7.3 可扩展性要求
- 后端能力统一通过 API 暴露
- 为后续多端应用预留接口
- 为后续协作能力预留数据结构

7.4 可维护性要求
- 模块划分清晰
- 业务与 AI 能力解耦
- 关键操作可追踪可审计

八、技术约束与选型
8.1 技术栈
- 后端：Java 17 + Spring Boot 3
- ORM：MyBatis Plus
- 前端：Vue 3 + TypeScript
- UI：Ant Design Vue
- 数据库：PostgreSQL
- 缓存：Redis
- 文件存储：MinIO
- 检索：Elasticsearch
- 消息队列：RabbitMQ
- AI 接入：Spring AI Alibaba
- 编辑器：TipTap

8.2 架构原则
- 前后端分离
- API 统一
- 业务模块化
- AI 与业务解耦
- 多端通用能力预留

九、版本规划
9.1 V1.0
- 单人个人知识管理版本
- 支持笔记、搜索、AI 问答、待办提取、提醒

9.2 V1.1
- 优化 AI 总结质量
- 优化搜索体验
- 增强提醒能力

9.3 V2.0
- 增加任务型智能体能力
- 增加更多自动化能力
- 支持多端统一体验

十、验收标准
10.1 基础功能验收
- 用户可正常注册登录
- 用户可正常创建、编辑、搜索、删除笔记
- AI 可对笔记进行总结与问答
- 系统可从笔记中提取待办并创建提醒

10.2 闭环验收
- 用户从记录到提醒到完成，形成完整闭环
- 所有关键动作有日志记录与来源回链

10.3 可扩展性验收
- 后续移动端或桌面端可复用同一套后端 API
- 当前代码结构支持功能扩展与模块拆分
