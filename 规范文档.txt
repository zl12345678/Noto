Noto · 知微
规范文档

一、项目介绍
1. 项目名称
Noto · 知微

2. 项目定位
一个面向个人用户的 AI 知识管理与行动清单工具，支持笔记记录、知识检索、AI 问答、待办提取、提醒执行，帮助用户把零散信息转化为可执行的行动。

3. 产品愿景
让用户不只是记录知识，而是能够真正找得到、问得出、总结清、做得动。

4. 核心理念
- 记录知识
- 理解知识
- 提炼行动
- 触发提醒
- 完成闭环

5. 目标用户
- 程序员
- 产品经理
- 学习型用户
- 自由职业者
- 有个人知识整理需求的人群

四、架构设计
1. 架构目标
- 当前先做 Web 端，保证快速上线
- 架构预留多端通用能力
- 支持个人知识管理、AI 问答、待办提醒、任务型智能体
- 优先保证可用性、可扩展性和可维护性

2. 技术选型
- 后端：Java 17 + Spring Boot 3
- ORM：MyBatis Plus
- 前端：Vue 3 + TypeScript
- UI：Ant Design Vue
- 数据库：PostgreSQL
- 缓存：Redis
- 文件存储：MinIO
- 全文检索：Elasticsearch
- 消息队列：RabbitMQ
- AI 接入：Spring AI Alibaba
- 编辑器：TipTap

3. 系统分层
- 表现层：Web 端，未来扩展 App、小程序、桌面端
- 接口层：REST API，辅以 WebSocket 或 SSE
- 业务层：笔记、搜索、AI、待办、提醒、智能体编排
- 数据层：PostgreSQL、Redis、Elasticsearch、MinIO
- 基础设施层：RabbitMQ、定时任务、日志监控

4. 核心模块
- 用户与认证模块
- 笔记模块
- 搜索模块
- AI 模块
- 待办模块
- 提醒模块
- 智能体编排模块
- 审计日志模块

5. 设计原则
- 前后端分离
- API 统一
- 业务模块化
- AI 与业务解耦
- 多端共用同一套后端能力
- 所有重要结果可追踪、可回链、可审计

6. 第一版架构边界
- 先做模块化单体，不拆微服务
- 先做单人可用版本，不做复杂协作
- 先保证笔记与检索可用，再增强 AI 和智能体能力
- 后续根据规模再拆分独立服务

7. 多端通用预留
- 所有核心能力通过统一 API 暴露
- 前端只负责呈现与交互
- 认证、数据模型、业务逻辑统一在后端
- 后续 App、小程序、桌面端可直接复用接口

五、版本目标
1. 第一版目标
- 个人可用
- 能记录知识
- 能搜索知识
- 能问知识
- 能提取待办
- 能提醒执行

2. 第二版目标
- 具备更好的 AI 理解能力
- 支持更多自动化能力
- 支持更完整的任务闭环

3. 长期目标
- 从个人工具逐步扩展到轻协作知识平台
- 从知识管理升级为知识到行动的智能助手
