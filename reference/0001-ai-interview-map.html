Reference 0001

Noto AI 面试速查图

目标：把项目讲成“私有知识到行动”的 AI 工程闭环，而不是普通聊天框。

一句话定位

Noto 是一个 AI 知识工作台：用 RAG 理解私人笔记，用可确认 Agent 把知识转成待办、提醒和复盘。

核心链路

能力你怎么讲代码入口
模型接入 通过 LangChain4j 的 DashScope Qwen chat、streaming chat、embedding model 接入通义千问。 LangChain4jAiConfiguration
RAG 索引 保存或手动重建时，将笔记分块，调用 embedding，保存 JSON 向量，并在 pgvector 可用时写入 vector(1024) 列。 NoteRagIndexServiceImpl
RAG 检索 问题先转 embedding，用 pgvector cosine 搜索；不可用时内存 cosine 扫描；再混合关键词提升和去重。 NoteRagSearchServiceImpl, NoteRetrievalService
回答生成 把检索片段、引用、对话上下文和用户偏好拼进 prompt；资料不足时输出 knowledge gaps。 AiServiceImpl.buildAskContext
SSE 流式 先发 references，再逐 token 发送回答，完成后保存会话和审计。 AiController.askStream, AiServiceImpl.askStream
可确认 Agent LLM 只负责规划工具调用；读操作直接执行，写操作生成 pending_confirm，用户确认后才写库。 AgentPlanner, AiAgentServiceImpl

高频追问

如何减少幻觉？

用私有笔记检索作为上下文，回答返回引用；资料不足时明确说缺信息，并给出知识缺口。

AI 不可用怎么办？

noto.ai.enabled=false 时加载 disabled service，主业务还能跑；部分待办提取还有 Markdown 规则兜底。

为什么写操作要确认？

笔记、待办、提醒属于用户数据。Agent 可以规划和预览，但创建、更新、删除必须进入确认链。

为什么用 pgvector？

数据已经在 PostgreSQL 中，pgvector 让向量检索和业务数据权限过滤在同一数据库内完成；HNSW 提升近似检索速度。
